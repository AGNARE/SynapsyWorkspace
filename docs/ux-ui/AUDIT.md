# Аудит интерфейса Synapse Workspace

Аудит проведён по трём источникам: ТЗ, существующие макеты и реализация в репозитории.
Статусы: **подтверждено** — проверено в источнике, **вероятно** — косвенные признаки,
**не проверено** — источник недоступен.

## 1. Источники и их состояние

| № | Источник | Полнота | Ограничения |
|---|---|---|---|
| S1 | ТЗ «Система мониторинга и управления проектной деятельностью» | требования | 135 абзацев, 1 таблица RBAC; **отдельного раздела UI нет** |
| S2 | Макеты «Ключевые страницы» | визуально | текст переведён в кривые, машинная проверка подписей невозможна; доска обрезана снизу |
| S3 | Макеты «Тесты» | визуально | 9 встроенных растров, из них 2 — скриншоты стороннего продукта (ElevenLabs Studio) |
| S4 | Репозиторий `Software-Engineering-KSTU/synapse` | код | ветка `feat/ux-ui-workspace-design` на момент аудита пуста |
| S5 | Figma-файл Synapse Workspace | полный | 20 экранов + 4 модальных окна |

## 2. Подтверждённые находки

| № | Находка | Влияние | Приоритет |
|---|---|---|---|
| 1 | **Два бренда в одном файле.** В мастер-канвасе одновременно KSTU Workspace и Synapse | путаница в навигации и в защите проекта | высокий |
| 2 | **Кыргызская локализация отсутствует.** Интерфейс только на русском, при этом ТЗ требует два языка | невыполнение требования | высокий |
| 3 | **Нет раздела UI в ТЗ.** Интерфейс проектируется без утверждённых экранов и состояний | дизайн нельзя принять формально | высокий |
| 4 | **Дрейф токенов.** В старых наборах встречаются цвета вне палитры (`#4F46E5` против `#6366F1` в разных ролях) | визуальная рассогласованность | средний |
| 5 | **Состояния не нарисованы.** Нет загрузки, ошибки, пустого состояния, отключённых элементов | разработчик придумывает их сам | высокий |
| 6 | **Растры вместо вектора.** Часть макетов — картинки base64, не редактируются | нельзя вносить правки | средний |
| 7 | **Иконки — заглушки 16×16** из простых фигур | вид «черновой» | средний |
| 8 | **Шрифт без подтверждённого покрытия** киргизской кириллицы (ӊ, ө, ү) | риск пустых глифов при локализации | средний |

## 3. Находки в репозитории

| № | Факт | Следствие |
|---|---|---|
| 1 | `docs/AI-RULES.md` — **0 байт** | файл создан и брошен, правила работы с ИИ не зафиксированы |
| 2 | `frontend/src/pages/overview/ui/OverviewPage.tsx` — **159 байт** | страница-заглушка: дизайн опережает реализацию |
| 3 | `frontend/src/widgets/layout/ui/Sidebar.tsx` — **6,3 КБ** | навигация реализована и её можно сверить с макетом |
| 4 | `frontend/src/shared/ui/` — `Button`, `Input`, `Badge`, `Avatar`, `Modal`, `Spinner` | компоненты уже в коде, дизайн-спецификация к ним не привязана |
| 5 | **Pull request — 0 за всё время** | нет ревью и нет следа «кто проверил» |
| 6 | Ветки не мержатся в `main` (7 веток, `main` = только инициализация) | работа команды не собирается в одну точку |
| 7 | Коммиты не ссылаются на issues | по истории нельзя понять, какая задача закрыта |
| 8 | В `docs/human_docs/use_case.png` — **234 КБ растра** | графема диаграммы не редактируется, вес в репозитории |

## 4. Что сделано по итогам аудита

- Собран набор из 17 экранов `1440×1024` в редактируемом SVG (живой текст, только вектор).
- Собраны 4 модальных окна.
- Собран редактируемый брендборд взамен растрового.
- Зафиксирован дизайн-контракт — [RULES.md](RULES.md): сетка, токены, типографика, запреты.
- Каждый файл прошёл автопроверку: XML, токены, запрещённые конструкции, кегль.

## 5. Открытые вопросы

1. Кыргызская локализация: нужен ли второй язык в макетах и какой шрифт покрывает глифы?
2. Wiki при отключённом модуле: как выглядит экран, если модуль не подключён?
3. Срок хранения архива: в макете 14 дней — подтверждено ли требованием?
4. Навигация: в части макетов есть Cycles/Projects, в ТЗ их нет. Какая структура верна?
5. Границы ответственности в ветке: какие каталоги закреплены за UX/UI?
