# Synapse Workspace — документация UX/UI

> Тестовый вариант раскладки: **C**. Содержимое одинаковое во всех вариантах,
> отличается только структура каталогов.

## Раскладка варианта C — «как у команды» (`docs/human_docs/`)

Файлы лежат плоско рядом, как у диаграммщиков: `use_case.md` + `use_case.png`.
Наш каталог встраивается в тот же `human_docs/`.

**Плюсы**
- Полное единообразие с существующим `docs/human_docs/use_case.md` — ничего нового
  команде запоминать не нужно.
- Короткие пути, всё в одном месте.
- Сразу видно, что страница относится к разделу человекочитаемой документации.

**Минусы**
- 20 страниц × 3 файла = 60 файлов в одном каталоге без группировки.
- Нет разделения «страницы» и «модальные окна» — всё в одной куче.
- `docs/human_docs/` перестаёт быть каталогом только диаграмм.

## Что внутри

| Файл | Назначение |
|---|---|
| `README.md` | этот файл: навигация и правила ведения |
| `RULES.md` | дизайн-контракт: сетка, токены, типографика, запреты, чек-лист |
| `BRAND.md` | брендборд: знак, градиенты, цветовые роли, шрифт |
| `AUDIT.md` | аудит интерфейса: источники, находки, открытые вопросы |
| `TASKS.md` | карта работ: issue → исполнитель → артефакт → статус |
| `pages/…` | по одному описанию на страницу, со ссылкой на Figma и превью |
| `modals/…` | по одному описанию на модальное окно |

## Как добавить новую страницу

1. Взять номер и имя из Figma: следующий свободный `NN-имя`.
2. Создать описание по шаблону соседней страницы (8 разделов).
3. Положить рядом SVG 1440×1024 и превью PNG.
4. В шапке описания указать ссылку на узел Figma.
5. Добавить строку в [TASKS.md](TASKS.md) со ссылкой на issue.

## Правила ведения

- Один экран — один SVG, один `.md`, одно превью.
- Все цвета и размеры — только из [RULES.md](RULES.md).
- Коммит ссылается на issue: `Refs #N` или `Closes #N`.
- Ветка: `feat/ux-ui-*` или `docs/ux-ui-*`.
