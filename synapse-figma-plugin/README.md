# Плагин: дизайн-система Synapse

Запускается в Figma и собирает **переменные, компоненты и иконки**. После этого
значение меняется в одном месте и расходится по всему: по компонентам, по их
инстансам и по обеим темам сразу.

## Почему плагин, а не мост

Мост рисует фреймы и текст — переменных и компонентов он не умеет вообще.
Создавать их может только плагин внутри Figma. Поэтому система собирается здесь,
а мостом потом рисуются экраны из готовых компонентов.

**Проверить плагин заранее нельзя** — он работает только внутри Figma. Если
что-то пойдёт не так, Figma покажет окошко с текстом ошибки и тем, что успело
собраться. Пришли текст — поправлю.

## Как установить

Нужен **Figma Desktop**: в браузере плагины разработчика тоже работают, но
с приложением надёжнее.

1. Скачай папку `synapse-figma-plugin` и **распакуй**. Файлы `manifest.json`
   и `code.js` должны лежать рядом.
2. Figma → **Plugins → Development → Import plugin from manifest…** → выбери
   `manifest.json`.
3. Открой файл **«Synapse Workspace»** — система собирается в текущий файл,
   на страницу **«Design System»**.
4. Запусти: **Plugins → Development → Synapse — сборка компонентов**.

Повторный запуск безопасен: переменные переиспользуются, прежние наборы
с нашими именами удаляются и собираются заново.

## Что появится

**Коллекция переменных «Synapse»** — 28 штук (25 цветов и 3 радиуса), с двумя режимами:

| Режим | Что внутри |
|---|---|
| **Light** | та же палитра, что в согласованных 19 экранах |
| **Dark** | новая «Aurora»: `#070B14`, поверхности `#101728`, акцент `#7C5CFF` |

Переменные не только цветные: радиусы контролов и карточек тоже переменные,
поэтому в тёмной теме они скруглены сильнее — это часть языка Aurora.

**Наборы компонентов** — всё привязано к переменным, а не к цветам напрямую:

| Набор | Вариантов | Что внутри |
|---|---|---|
| `Button` | 20 | основная, вторичная, призрачная, опасная, иконка × обычное, наведение, фокус, отключённая |
| `Input` | 8 | поле и список × обычное, фокус, ошибка, отключённое |
| `Badge / Status` | 6 | шесть статусов задачи |
| `Badge / Priority` | 3 | три приоритета |
| `Chip` | 2 | обычный и активный |
| `Checkbox` | 2 | снят и отмечен |
| `Toggle` | 2 | выключен и включён |
| `Avatar` | 4 | 16, 24, 32, 40 |
| `Card` | 2 | обычная и метрика |
| `Row / Task` | 3 | строка задачи: обычная, наведение, выбранная |
| `Icon` | 37 | стрелки, действия, объекты, статусы — обводка 1.6, поле 24×24 |

Всего **89 вариантов компонентов** в одиннадцати наборах.

## Как переключать тему

**У всей страницы.** Правый клик по странице в списке слоёв → **Apply variable
mode** → `Synapse` → `Dark`. Всё, что на странице, перерисуется.

**У одного кадра.** Выдели фрейм → в правой панели у **Variables** выбери `Dark` —
остальная страница останется светлой.

## Как менять «в одном месте»

Открой **Local variables** (иконка переменных в правой панели), найди, например,
`color/action`. Поменяй значение в режиме Light. Изменится всё: цвет основной
кнопки, ссылок, активных пунктов навигации — во всех компонентах и инстансах.

Это и есть смысл системы: цвет не «нарисован», а **выдан** компоненту.

## Если запустить второй раз

Наборы `Button`, `Input`, `Badge / Status`, `Badge / Priority`, `Chip`,
`Checkbox`, `Toggle`, `Avatar`, `Card`, `Row / Task`, `Icon` удаляются и
собираются заново. Переменные переиспользуются — твои правки в них сохранятся.

## Что можно дописать

Модальные окна, дерево базы знаний, колонку канбана, диаграмму Ганта.
Логика та же: новый набор добавляется в `code.js`.
